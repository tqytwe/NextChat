# APP 变更记录

## 3.0.34 (334) - Direct 真机测试候选

- 图片生成与内容创作工作台由同一个账号级 FIFO 调度器选择最早的持久化任务；
  两个页面仍各自保存其结果和项目字段，不复制出第二份任务真相。普通网络、
  上游和单模型失败终结当前任务并继续后续任务；登录、余额和权限失败同时阻塞
  同账号两种来源的后续任务，用户显式恢复后才重新推进。
- Direct 的认证应用壳在首屏稳定后挂载无界面的图片/工作台队列执行器。用户离开
  创作页、回到首页、前后台切换、网络恢复或进程重启后，都从同一份持久化任务记录
  继续选择任务；可见页面仅以更高优先级接管取消和进度控制。账号变更不会复用旧
  页面闭包或旧会话，`reconciling` 请求也不会被自动重发。
- 简单生图在释放内存运行标记后再次触发持久化唤醒，修复首项失败时后续项可能
  永久显示排队中的竞态。提交前校验失败也会把已经持久化的任务明确标记为失败或
  待恢复，不能留下不可执行的 `queued` 记录。
- 工作台把 `submitting` 和 `running` 的中断都迁移为 `reconciling`，不自动重发；
  后续未提交镜头继续推进，用户可明确重试已核对但无法恢复结果的镜头。账号切换
  中的任务会进入登录待恢复状态而非无限循环。
- 视频工程将结果写回提交时的镜头提示词快照，避免用户在等待期间编辑可见输入框
  后污染工程历史。真实账号对账已证实 `video视频 (45)` 与 `Grok Heavy (65)`
  的工作区、视频会话切换和专用 bootstrap 状态，详见
  [`2026-09-02-domestic-media-contract-diagnostic.md`](2026-09-02-domestic-media-contract-diagnostic.md)。
- 素材页区分 IndexedDB 读取失败与远端增量同步失败；生产 `/assets/sync` 的 404
  仅显示局部同步提示，不再把空的本机素材页误报成读取失败。
- 静态验收：TypeScript、九组定向 Jest（145 项）、四语言静态校验和文档治理已通过。
  本轮仅修改国内 Direct 客户端；未部署、未发布、未构建或改动 Play 制品，真实手机
  对视频组实际提交、队列、素材和四语言的验收仍是候选转正式的前提。
- 构建：Dell `codex` 固定工具链生成并独立验签 `public/downloads/jisudengchat-android.apk`，
  SHA-256 为 `b3d87518756f9fcae000ec31ae57432479992dd6b85e1fe357ed1dbaebc78f7b`，
  包名 `com.jisudeng.chat`、版本 `3.0.34 (334)`，签名证书 SHA-256 为
  `cd7abbd79daf6648a429ff34d7450b18cfb6b416e660b2f5169178e0a488627e`，构建源提交为
  `907828c8`。

## 3.0.33 (333) - Direct 真机测试候选

- 图片与内容工作台：统一为当前账号按创建时间推进的本机 FIFO。普通网络、上游或单模型失败
  只终结当前任务并继续后续任务；登录、余额和权限问题把同账号后续任务标记为待恢复，用户
  修复后显式恢复。跨网络边界的中断请求保持 `reconciling`，不会自动重发或重复扣费。
- 内容创作工作台：镜头数量支持 `1–16`、试生成和补齐余量；镜头可编辑、复制、排序和删除，
  可通过已授权的聊天模型获得提示词改写候选并由用户采纳或还原。工程包 v2 按 manifest 输出顺序
  恢复，缺失已声明输出时拒绝导出或导入。
- 素材库：先读取账号隔离的 IndexedDB 索引，再进行远端增量同步。单个下载、大小或哈希失败
  不清空其他素材；失败项可独立重试，错误仅保留安全诊断元数据。
- 视频：purpose-scoped 视频分组切换不再覆盖完整工作区；工作区和专用 bootstrap 按稳定
  `groupId/modelId` 合并，能力字段缺失时使用稳定默认选项。新增本机视频工程，保存简介、剧本、
  角色、场景、道具、故事事实、分镜与任务关联；按镜头顺序提交已有视频任务，已存在任务先核对。
  工程包包含可用的参考素材和本机结果并校验 ZIP 路径、大小与 SHA-256。
- 范围：只改 Direct 客户端，无后端接口、数据库迁移、计费规则、模型后台、部署或 Play 制品变更。
- 构建：Dell `codex` 固定工具链通过 doctor、Direct Firebase 校验、离线 Gradle 签名、制品校验，
  生成 `public/downloads/jisudengchat-android.apk`，SHA-256 为
  `55321a4adf8214798db170981ed3e75f7e960dfdb4920fd990d18bd34744a4dc`，包名
  `com.jisudeng.chat`、版本 `3.0.33 (333)`、证书指纹均已验证。APK 源码提交为 `1a846ed6`。
- 验收：TypeScript、十个定向 Jest 套件（144 项）和四语言静态检查通过。真实账号的
  `Grok Heavy` / `video视频` 全部模型、真实视频提交和真机 UI 仍需用户验收；
  在这些证据齐全前保持 `candidate`，不标记为已发布。
